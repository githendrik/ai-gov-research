# The AI Gov Digest

A weekly digest of AI governance, regulation, and safety news. Static site built with [Hugo](https://gohugo.io/), deployed on Vercel, source content kept verbatim and transformed at build time.

## Architecture

```
docs/                          # Verbatim source markdown (committed, source of truth)
  2026-08-04-ai-governance.md
content/posts/                 # Generated by transformer, gitignored
scripts/transform_docs.py      # docs/*.md -> content/posts/*.md (frontmatter, citations)
layouts/                       # Custom brutalist theme
assets/css/main.css
hugo.toml                      # Hugo config (modern format, needs Hugo >= 0.110.0)
vercel.json                    # Build command wires transformer + hugo
package.json                   # Local dev scripts
```

**Flow:** drop a file into `docs/` → push to `main` → Vercel auto-deploys. The transformer runs inside Vercel's build command, not in CI. No GitHub Actions.

## Source format

Files in `docs/` follow a fixed shape (the upstream research pipeline produces them; do not edit by hand unless the pipeline is down):
- Filename starts with `YYYY-MM-DD-` — the publish date is parsed from this.
- First line is an `# H1` title — promoted to frontmatter `title` and removed from the body.
- Sections use `## Heading` (Summary, Key Developments, Emerging Themes, Open Questions).
- Key Developments items use `### N. Title` with bold-led fields: Source / URL / Category / Summary / Why it matters.
- Citation markers like `[68]` or `[77][93]` are kept as research provenance — the transformer rewrites them to `<sup>68</sup>` / `<sup>77,93</sup>`.

The source files in `docs/` are **never modified** by the build. The transformer only writes to `content/posts/`.

## Local dev

Prereqs: Homebrew Hugo (`brew install hugo`) and Python 3.9+.

```bash
npm install          # once, for concurrently
npm run dev          # transformer --watch + hugo server on :1313
```

Or run the pieces manually:

```bash
python3 scripts/transform_docs.py --watch    # one terminal
hugo server --port 1313                        # another terminal
```

Edit any `docs/*.md` → site hot-reloads. Generated `content/posts/*.md` is gitignored; do not commit it.

## Build

```bash
python3 scripts/transform_docs.py && hugo --minify --gc
```

Output goes to `public/`. RSS feeds: `/index.xml` (site-wide) and `/posts/index.xml` (section).

## Deploy

Vercel auto-deploys on every push to `main` using the build command from `vercel.json`:

```
python3 scripts/transform_docs.py && hugo --minify --gc
```

### CRITICAL: pin the Hugo version on Vercel

Vercel's default Hugo runtime is ancient (0.58.x). That version predates `hugo.toml` support (added in v0.110.0), so the entire config is silently ignored — site builds with empty `{{ .Site.Title }}`, empty `baseURL`, no description, broken links. The custom theme will *look* like it loaded (CSS assets don't depend on config) but all text bound to config values is blank.

**Fix (one-time, in the Vercel dashboard):**
1. Project → Settings → Environment Variables
2. Add `HUGO_VERSION` = `0.164.0` (match your local `hugo version`)
3. Apply to Production, Preview, and CLI
4. Redeploy

Without this, every redeploy ships a broken header. See `AGENTS.md` for the full debugging trail.
