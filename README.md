# The AI Gov Digest

A weekly digest of AI governance, regulation, and safety news. Static site built with [Hugo](https://gohugo.io/), deployed on Vercel, source content produced by an automated research pipeline and transformed at build time. Bilingual: English (at root) and German (at `/de/`), served via Hugo's built-in i18n.

## Hero images

Each post can have a hero image. The image is generated by the upstream bridge script (via haimaker `gpt-image-1-mini`), cropped to 16:9, compressed, and saved as `static/images/<stem>.png` — same filename stem as the markdown in `docs/`.

- The transformer (`scripts/transform_docs.py`) checks for `static/images/<stem>.png` and injects `image: /images/<stem>.png` into the frontmatter if it exists.
- The Hugo template (`single.html`) renders the hero image with a brutalist title overlay: orange (`#ff4500`) block at the bottom with black text, 4px black border, matching the site header style. Contrast is guaranteed by the solid block, not by text shadows.
- If no image exists, the post renders without a hero — the template uses `{{ with .Params.image }}` and falls back to a plain title.
- Mobile: font size and hero height scale via `clamp()` at the `max-width: 480px` breakpoint.

## Source format

Files in `docs/` follow a fixed shape (produced by the upstream research pipeline; do not edit by hand):
- Filename starts with `YYYY-MM-DD-` — the publish date is parsed from this.
- German files use the `.de.md` suffix (e.g. `2026-08-04-ai-governance.de.md`); English files use plain `.md`.
- First line is an `# H1` title — promoted to frontmatter `title` and removed from the body.
- English sections: Summary, Key Developments, Emerging Themes, Open Questions.
- German sections: Zusammenfassung, Kernentwicklungen, Aufkommende Themen, Offene Fragen.
- Key Developments items use `### N. Title` with bold-led fields: Source / URL / Category / Summary / Why it matters.
- Citation markers like `[68]` or `[77][93]` are kept as research provenance — the transformer rewrites them to `<sup>68</sup>` / `<sup>77,93</sup>`.
- The automation produces both languages in one model call, separated by a `---DE---` delimiter. The bridge splits them into two files with identical item numbering, citations, and URLs (only prose is translated).

The source files in `docs/` are **never modified** by the build. The transformer only writes to `content/en/posts/` and `content/de/posts/`.

## The upstream pipeline (homelab CT 104)

The research pipeline runs on a Proxmox LXC container (`lab` host, CT 104). Full reference: `Homelab/reference/gmktec-m6-local-llm-guide.md` §15 in the Obsidian vault.

### Components

| Component | Type | Purpose |
|---|---|---|
| `ai-gov-research` model | Open WebUI custom model | Wraps `deepseek/deepseek-v4-flash` (haimaker) with `web_search` + `builtin_tools` capabilities |
| Automation `134937c8-...` | Open WebUI Automation | Weekly RRULE `FREQ=WEEKLY;BYDAY=MO;BYHOUR=7`, fires the research prompt |
| `bridge.py` | Python script (systemd oneshot) | Extracts digest from chat API → writes file → git push + image gen |
| `ai-gov-bridge.timer` | systemd timer | Fires bridge 30 min after automation (Mon 07:30), `Persistent=true` |
| `oikb-watch.service` | systemd service | `oikb watch /opt/ai-gov-research/digests --kb-id 2d9cf10f-...` — incremental SHA-256 sync |
| KB "AI Governance Research" | Open WebUI Knowledge Base | RAG corpus; attached to the model so the automation can dedup against past digests |
| Deploy key | SSH keypair | `/opt/ai-gov-research/.ssh/deploy_key` — scoped to this repo, write access |

### How it fits together

1. **Monday 07:00** — Open WebUI Automation fires. `deepseek-v4-flash` runs ~20 agentic SearXNG search rounds, produces a cited markdown digest. The KB is attached to the model (`rag.top_k = 20`) so it retrieves fragments from past digests for dedup.
2. **Monday 07:30** — `ai-gov-bridge.timer` fires `bridge.py`:
   - Fetches the automation's latest successful run via the Open WebUI API.
   - Extracts the assistant reply from `chat.history.messages[currentId].content`.
   - Strips model preamble (everything before `# AI Governance`).
   - Writes the digest to `/opt/ai-gov-research/digests/` (oikb watches this → syncs to KB).
   - Copies to `blog-repo/docs/` and does `git pull --rebase` + `git push` (markdown commit).
   - Generates a 1024×1024 hero image via haimaker `gpt-image-1-mini`, crops to 16:9 center with Pillow, compresses, saves to `blog-repo/static/images/`, commits + pushes (image commit).
3. **Continuous** — `oikb-watch.service` watches `digests/` and syncs new/modified files into the Knowledge Base via incremental SHA-256 diff. The KB grows weekly; the automation reads from it for dedup.
4. **Push to GitHub** — Vercel auto-deploys: transformer runs, Hugo builds, site goes live at `aigov.philine.ch`.

### Dedup mechanism

The Knowledge Base is attached to the `ai-gov-research` model. When the automation runs, Open WebUI's RAG pipeline retrieves up to 20 semantically similar chunks from previous digests and injects them into the prompt. The model sees what it produced before and avoids repeating the same items.

### Managing the pipeline

- **Run automation now**: `curl -X POST http://localhost:3000/api/v1/automations/134937c8-9abd-4781-8d6b-bbf5202327b5/run -H "Authorization: Bearer <api-key>"`
- **Run bridge manually**: `/opt/ai-gov-research/bridge.py`
- **Check oikb sync**: `journalctl -u oikb-watch.service --since '5 min ago'`
- **Pause/resume**: toggle via Open WebUI UI (User Menu → Automations) or `POST /api/v1/automations/{id}/toggle`

## Local dev

Prereqs: Homebrew Hugo (`brew install hugo`) and Python 3.9+.

```bash
npm install          # once, for concurrently
npm run dev          # transformer --watch + hugo server on :1313
```

Or run the pieces manually:

```bash
python3 scripts/transform_docs.py --watch    # one terminal
hugo server --port 1313                        # another terminal
```

Edit any `docs/*.md` → site hot-reloads. Generated `content/posts/*.md` is gitignored; do not commit it.

## Build

```bash
python3 scripts/transform_docs.py && hugo --minify --gc
```

Output goes to `public/`. RSS feeds: `/index.xml` + `/posts/index.xml` (EN), `/de/index.xml` + `/de/posts/index.xml` (DE).

## Deploy

Vercel auto-deploys on every push to `main` using the build command from `vercel.json`:

```
python3 scripts/transform_docs.py && hugo --minify --gc
```

Domain: **aigov.philine.ch**

### CRITICAL: pin the Hugo version on Vercel

Vercel's default Hugo runtime is ancient (0.58.x). That version predates `hugo.toml` support (added in v0.110.0), so the entire config is silently ignored — site builds with empty `{{ .Site.Title }}`, empty `baseURL`, no description, broken links. The custom theme will *look* like it loaded (CSS assets don't depend on config) but all text bound to config values is blank.

**Fix (one-time, in the Vercel dashboard):**
1. Project → Settings → Environment Variables
2. Add `HUGO_VERSION` = `0.164.0` (match your local `hugo version`)
3. Apply to Production, Preview, and CLI
4. Redeploy

Without this, every redeploy ships a broken header. See `AGENTS.md` for the full debugging trail.
